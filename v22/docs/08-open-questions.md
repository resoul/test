## Состояние и реактивность

Обсуждение ещё не проводилось. Исходные наблюдения по Trellis и Flux:

- В Trellis подписка живёт на уровне хоста (`bridge.bindState` / `bindFlux`), а экран сам
  сравнивает показанное с новым и сам кэширует дочерние ноды. Кэш закрывается `NodeCache`
  ([04](04-conditionals-and-responsive.md#7-кэш-нод-для-динамических-списков)), остальное
  — нет.
- Flux хорош для потоков (сеть, debounce, `flatMapLatest`), но как UI-состояние неудобен.
  Разбор Flux 1.2.1 (версия, закреплённая в Trellis), 2026-09-24:
  - **Всё асинхронно.** `Flux<T>` — фабрика `AsyncStream`; `sink`/`sinkOnMain` запускают
    `Task`, и каждый оператор (`map`, `onMain`, `scan`…) — ещё один `Task` + `AsyncStream`.
    Значение доходит до UI не раньше следующего хода MainActor, цепочка из N операторов —
    N переходов.
  - **Нет синхронного текущего значения.** `CurrentValue` — `actor`: `value` читается через
    `await`, запись — `await set(…)`, из MainActor-модели — `Task { await set(…) }`.
    Повтор текущего значения новому подписчику тоже асинхронный (регистрация через `Task`),
    поэтому `bindFlux` в Trellis требует отдельный `initial` для первого кадра.
  - **Нет слияния по кадру.** `bindFlux` документирует: N значений от Flux — N доставок и N
    коммитов; слияние — забота продюсера (`throttle`/`debounce`).
  - **Порядок записей.** В `S32_FluxFilterFeed` `.loading` и результат пишутся из двух
    независимых `Task { await set(…) }`. Проверено чтением кода: на практике порядок
    сохраняется — обе задачи создаются на MainActor с одним приоритетом, между ними ~700 мс,
    устаревший результат отсекает `EffectOwner`. Формально гарантии нет: очередь актора
    упорядочена по приоритету, FIFO не обещан. Дефектом не считаю — не воспроизводится;
    это довод за синхронное ядро, где порядок записей — порядок вызовов.
  - Внутри Flux — `NSLock` и `@unchecked Sendable` (`Pipe`, `Subscription`,
    `SubscriptionBag`). Это код зависимости, не наш; правило AGENTS его не касается, но
    ядро состояния v22 так писать нельзя.

**Согласовано (2026-09-24):**

- ядро состояния — синхронное, на MainActor, модуль `StateCore` (не `State`: модуль и тип
  с одним именем ломают квалификацию, как `Layout`); Flux — адаптер `StateFlux`, от Flux
  1.3.0;
- подписка — **автоматическая по чтению**: что прочитано в `layoutSpec()`, пересчитывает
  раскладку этой ноды; что прочитано в `update()`, вызывает `update()`. Явный `Observer`
  остаётся запасным путём;
- отслеживание — **своё**, не Observation-фреймворк: минимум остаётся iOS 16 / tvOS 16 /
  macOS 14, как у Flux и Trellis; мост к `@Observable` для iOS 17+ — возможен позже.

**Сделано (2026-09-24), срез:** `StateCore` — `State`, `Computed` (ленивый, кэш, равный
результат не распространяется), `Observer`, `Effect`, `untracked`, `StateUpdates`
(слияние записей до flush, порядок наблюдателей по созданию, предел раундов на циклы).
15 тестов на Linux. Слой нод, `StateFlux` и планировщик flush «перед кадром» — не сделаны.

Открыто:

- гранулярность моделей: `State` на свойство или модель целиком с `update(model)`;
- как в этот путь встраивается намерение анимации (в Trellis — P6.2, `bindFlux(animation:)`);
- события и действия — замыкания (как D22 Trellis) или что-то ещё.

## Layout

- Имя метода раскладки (`layoutSpec()` / `arrange()` / `makeLayout()`) и имя метода
  «раскладка изменилась».
- Ручные `addSubnode`/`removeFromSupernode` у ноды с `layoutSpec()`.
- Протокол собственных контейнеров (расширяемость словаря).
- Больше двух веток `Breakpoint`.
- Значения встроенных порогов — проверить на экранах Playground; переопределение их темой.
- Политика освобождения нод в `NodeCache`.
- Анимации появления/исчезновения (`.transition`).

## Адаптеры

- `node.view` по требованию.
- Жизненный цикл хоста, созданного `addSubnode`.
- Смешанные деревья (вторая очередь).
