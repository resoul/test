# Открытые вопросы

## Продукт

- **Trellis v2 или отдельная библиотека.** От ответа зависят имена модулей, нужна ли
  совместимость с текущим API Trellis и миграция экранов Playground,
  `CollectionNode`/`Pager`.

## Состояние и реактивность

Обсуждение ещё не проводилось. Исходные наблюдения по Trellis и Flux:

- В Trellis подписка живёт на уровне хоста (`bridge.bindState` / `bindFlux`), а экран сам
  сравнивает показанное с новым и сам кэширует дочерние ноды. Кэш закрывается `NodeCache`
  ([04](04-conditionals-and-responsive.md#7-кэш-нод-для-динамических-списков)), остальное
  — нет.
- Flux хорош для потоков (сеть, debounce, `flatMapLatest`), но как UI-состояние неудобен:
  `CurrentValue` — `actor`, и запись из MainActor-модели идёт через `Task { await set(…) }`;
  каждый оператор — отдельный `Task` + `AsyncStream`.
- **Требует проверки, не подтверждено:** в `Playground/Shared/Scenarios/S32_FluxFilterFeed.swift`
  две записи в `CurrentValue` (`.loading` и результат) идут из двух независимых
  неструктурированных `Task`, и порядок их выполнения формально не гарантирован. Не
  воспроизводилось; если подтвердится — запись в `docs/defects.md` Trellis.

Предложение для обсуждения: синхронное ядро состояния на MainActor (модуль `State`), Flux
— адаптер к нему (`StateFlux`). Вопросы:

- где подписка: у хоста, у ноды с временем жизни «пока смонтирована», или автоматическое
  отслеживание зависимостей по чтению (как `@Observable`; Observation-фреймворк требует
  iOS 17 / macOS 14, текущий минимум Trellis — iOS 16 / tvOS 16);
- как смена состояния запрашивает пересчёт раскладки (сейчас — ручной
  `markArrangementDirty()`);
- как в этот путь встраивается намерение анимации (в Trellis — P6.2, `bindFlux(animation:)`).

## Layout

- Имя метода раскладки (`layoutSpec()` / `arrange()` / `makeLayout()`) и имя метода
  «раскладка изменилась».
- Ручные `addSubnode`/`removeFromSupernode` у ноды с `layoutSpec()`.
- Протокол собственных контейнеров (расширяемость словаря).
- Больше двух веток `Breakpoint`.
- Значения встроенных порогов — проверить на экранах Playground; переопределение их темой.
- Политика освобождения нод в `NodeCache`.
- Анимации появления/исчезновения (`.transition`).

## Адаптеры

- `isFlipped` в AppKit: переворачивать координаты или требовать flipped-view.
- `node.view` по требованию.
- Жизненный цикл хоста, созданного `addSubnode`.
- Смешанные деревья (вторая очередь).

## Тема

- Имена токенов отступов ([09](09-theme.md#имена-отступов--открыто)).
- Как `UIView`/`NSView`-адаптер получает не стандартную тему.
- Состав темы по умолчанию помимо отступов; переключение и анимация смены темы.

## Flexbox

- Результат прогона текущего `FlexboxEngine` через conformance-набор
  ([06](06-flexbox-conformance.md#первый-шаг)) — определяет, дорабатывать движок или
  писать новый.
- Grid как второй движок (`GridEngine`, D11 Trellis) — вне первой очереди v22.
