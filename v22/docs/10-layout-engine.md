# Движок раскладки

## Решение

**Статус: направление предварительно согласовано** — новый flex-движок на основе
старого `FlexboxEngine` Trellis: инфраструктура переносится, алгоритм пишется заново по
шагам спецификации CSS. Остальное в документе — **предложено**.

## Почему не чинить старый

Первый прогон conformance-набора ([06](06-flexbox-conformance.md)) дал 12 причин
расхождения с Chromium ([defects.md](../../docs/defects.md) #95–#106). Они не
сосредоточены в одном месте — они есть в каждой фазе алгоритма:

| Фаза | Дефекты |
|---|---|
| Базовый размер и минимальный размер item | #101 (`min-width: auto`), #100 (`min > max`) |
| Распределение свободного места | #98 (нет цикла заморозки), #99 (сумма grow < 1) |
| Поперечный размер | #96 (stretch без margin), #97 (stretch без min/max), #106 (aspect-ratio, обрезка явного размера) |
| Размещение | #95 (margin не в длине линии и не в курсоре), #102 (`wrap-reverse`) |
| Absolute | #103, #104, #105 |

Причина общая: структура движка не повторяет структуру спецификации. В нём нет понятия
«внешний размер item» (размер + margin), поэтому margin по отдельности забыт в
размещении, в stretch и в `justifyContent`. Placement заново выводит stretch и позиции
отдельно от measure, поэтому min/max и aspect-ratio теряются между проходами. Нет цикла
заморозки §9.7, поэтому clamp и дробные grow считаются в один проход.

Старый движок уже чинили в сторону CSS точечно: [ADR 0006](../../docs/adr/0006-flex-line-cross-size-fills-definite-frame.md)
(линия заполняет definite frame), [ADR 0009](../../docs/adr/0009-flex-basis-is-max-content.md)
(basis `auto` = max-content). Каждая следующая правка ложится ещё одним слоем на
структуру, которая спецификации не соответствует. Кроме того, v22 всё равно меняет вход
движка: элементы раскладки вместо нод, `Breakpoint`, значения `from:`
([03](03-layout-api.md), [04](04-conditionals-and-responsive.md)).

## Что переносится из старого движка

Это не алгоритм, а инфраструктура, каждая часть которой оплачена найденным дефектом или
замером.

| Что | Откуда | Почему сохраняем |
|---|---|---|
| Контракт отмены `throws -> LayoutResult`, `LayoutContext` | D09, D10 | отменённая работа не коммитится; пустой результат — не отмена |
| Checkpoints отмены: вход контейнера, границы линий, каждые 256 item | D09, дефект #16 | латентность отмены 0.08 ms на линии из 5000 item |
| Request-local кэш измерений без LRU | ADR 0007, дефект #13 | без него вложенность — 2^depth |
| Размещение переиспользует измерение родителя | ADR 0008, дефект #14 | без него вложенность — O(depth²) |
| Basis `auto` = max-content, детям — пространство из собственного размера | ADR 0009, дефекты #24–#28 | совпадает с CSS §7.2.3/§9.2 и убирает удвоение состояний |
| Бегущие суммы вместо `reduce` по линии | дефект #15 | O(n) на широкой линии |
| Один массив placements на весь проход | дефект #23 | O(nodes), не O(nodes × depth) |
| Индекс результата по id, дубликаты — диагностика | weave-analysis §3.1 | O(1) `placement(for:)` |
| `PixelRoundingPolicy` | Trellis | округление к пикселям экрана |
| Трассировка `Log.on(.measure/.place, …)` с `#id` | AGENTS.md | читаемый лог на устройстве |
| Замеры Bench: `deep-local-edit`, `overflow-chain`, `cancel-latency`, `text-list`, `wide` | C31 | новый движок не должен быть медленнее |

## Что пишется заново: алгоритм по шагам CSS §9

Каждый шаг — отдельная чистая функция с номером раздела спецификации в имени или
комментарии. Проверяемость важнее краткости: по коду должно быть видно, какой пункт
спецификации где реализован.

| Шаг | Раздел CSS Flexbox | Закрывает |
|---|---|---|
| Доступное пространство | §9.2 п.2 | — |
| Базовый размер и гипотетический main-размер item, **автоматический минимальный размер** | §9.2 п.3, §4.5 | #101, #100 |
| Внешний размер item = размер + margin — единое понятие для всех последующих шагов | §9.3 | #95, #96 |
| Сбор flex-линий по внешним размерам | §9.3 | — |
| Разрешение гибких длин: цикл заморозки, сумма факторов < 1, clamp min/max | §9.7 | #98, #99 |
| Гипотетический поперечный размер, размер линии | §9.4 | — |
| `align-content`, stretch линий, `wrap-reverse` (cross-start/cross-end) | §9.4, §8.4 | #102 |
| Stretch item: минус cross-margin, затем clamp min/max, затем aspect-ratio | §9.4 п.11 | #96, #97, #106 |
| Выравнивание по главной оси: **`margin: auto`**, затем `justify-content` | §9.5, §8.1 | #95, `unsupported` |
| Выравнивание по поперечной оси: `margin: auto`, `align-self`, baseline | §9.6, §8.3 | — |
| `order` | §5.4 | `unsupported` |
| Absolutely positioned: padding box, растяжение между смещениями, статическая позиция по `justify-content`/`align-*` | §4.1, CSS Position | #103, #104, #105 |
| Явный размер не обрезается доступным местом — переполнение, как в CSS | §9.2, §9.4 | #106 |
| Intrinsic-размеры контейнера (min-content / max-content) | §9.9 | нужно для #101 и текста |

## Ключевые структуры

- **Item** — внутренний и внешний размер по обеим осям, базовый размер, гипотетический
  размер, минимальный/максимальный, флаг «заморожен», целевой размер. Внешний размер —
  единственный вход для линий, свободного места и курсора.
- **Line** — item, сумма внешних размеров, поперечный размер, baseline.
- **Измерение листа** — три запроса вместо одного: min-content, max-content и размер под
  доступное пространство. Без min-content невозможен автоматический минимальный размер
  (#101) и правильное поведение текста в строках. `ContentMeasurer` Trellis расширяется
  или заменяется — открыто.

## Вход и выход

Вход — дерево элементов раскладки модуля `Layout` ([02](02-modules.md)), не `Node`:
`Layout` не знает слова «нода». Идентификатор элемента — непрозрачный id, который
адаптер (`Nodes`, `LayoutUIKit`, `LayoutAppKit`) сопоставляет со своим объектом. Токены
темы и именованные пороги к этому моменту уже превращены в числа
([09](09-theme.md#когда-токен-превращается-в-число)); `Breakpoint` и `from:` — единственное
расширение сверх CSS, которое движок решает сам.

Выход — frame каждого элемента в координатах корня, как сейчас.

## Как ведётся работа

1. **Conformance first.** Новый движок стартует с 0 из 142, и число проходящих кейсов
   только растёт. Baseline фиксирует итог каждого кейса; тест падает на любое изменение
   ([README набора](../../Conformance/CSSFlexbox/README.md)).
2. **Эталон — Chromium, не ожидания старых тестов.** Тесты `FlexboxAlgorithmTests` /
   `FlexboxEngineTests` перенесены из Weave с прежними ожиданиями. Там, где они
   противоречат браузеру, для v22 побеждает браузер; каждое такое противоречие
   записывается явно, а не переписывается молча.
3. **Отклонение от CSS — только осознанное.** Если v22 где-то намеренно ведёт себя иначе
   (например, `border-box` вместо `content-box` по умолчанию), это строка в этом
   документе и кейс с пометкой, а не расхождение в baseline.
4. **Производительность — не хуже старого.** Те же фикстуры Bench C31 для обоих движков.

## Статус E1

**Критерий выполнен (2026-09-24): 142 из 142**, `unsupported` нет — `margin: auto` и
`order` поддержаны. Для сравнения: старый движок Trellis — 107 / 29 fail / 6 unsupported.
Код — `v22/Sources/LayoutCore`, прогон — `v22/Tests/LayoutCoreTests`, baseline —
[expectations/engine.json](../../Conformance/CSSFlexbox/expectations/engine.json), отчёт —
[reports/engine.md](../../Conformance/CSSFlexbox/reports/engine.md). Собирается и проходит на
Linux (Swift 6.4); на Mac не прогонялось.

Честная оговорка: алгоритм писался при известном наборе из 142 кейсов, поэтому 142/142 —
необходимое, но не достаточное условие. Поэтому набор расширен 400 случайными деревьями
(`fixtures/random.json`, seed 2026), которых движок «не видел».

**Случайные деревья: 362 из 400** (первый прогон — 258). Разбор расхождений дал ~20 правил
CSS и поведения Chromium, которых не было в ручном наборе, — реестр дефектов #107–#117
(все исправлены). Главные: ширина definite, как только известна (§9.8 ограничивает
высоты); stretch только при поперечном `auto`; basis из `width` до min/max и неразрешимый
процент basis как `content`; собственная ширина row — по вкладам детей, column с `wrap` —
по самому широкому элементу (как в Blink); safe-fallback `space-around/evenly`; пропорции
(перенос min/max, автоминимум по зависимой оси); absolute (auto-margin, RTL, definite
высота).

Остаётся 38 (#118, открыт): 36 — сочетания `aspect-ratio` и/или `absolute`, 2 не
разобраны. Ядро flex без них совпадает с Chromium на всех сгенерированных деревьях, кроме
этих двух.

Найдено по ходу:
- модуль не может называться `Layout` — это протокол SwiftUI; модуль назван `LayoutCore`;
- тип длины не может называться `Dimension` — это класс Foundation; назван `Length`.

## Статус E2: текст

**Размеры по содержимому — сделано (2026-09-24).** Лист получил протокол
`ContentMeasurer`: min-content ширина, max-content ширина и высота при заданной ширине.
`LeafContent` — `.size` (картинка) или `.measured` (текст). Лист с измеряемым содержимым
сначала получает ширину (известную, либо min-/max-/fit-content по ограничению), затем
высоту при ней; ширина, зажатая min/max, переносит текст заново.

Проверка: «текст» в эталонах — слова-блоки `inline-block` фиксированной ширины и одной
высоты строки; Chromium переносит их как текст, но без шрифтов, а тестовый измеритель
переносит так же жадно. Ручные текстовые кейсы — **12 из 12**, случайные деревья с
текстом (`fixtures/random-text.json`, seed 7) — **176 из 200**; все падения, кроме
известного хвоста `aspect-ratio`/`absolute` (#118), закрыты (#119).

Не сделано в E2: выравнивание по базовой линии (`align-items: baseline`) — нужен ещё
запрос первой базовой линии у измерителя.

## Статус: `FlexContainer` для `UIView`/`NSView`

**Сделано (2026-09-24), на Apple-платформах ещё не прогонялось.**

- `LayoutCore/DSL` — платформо-нейтральный DSL: `LayoutSpec` (`FlexContainer` — его
  псевдоним), `LayoutBuilder` (`if`, `if let`, `switch`, `for`, опциональные элементы),
  модификаторы элемента и контейнера, `apply(in:direction:scale:)` с привязкой краёв к
  пиксельной сетке, `measure(width:height:)`; протоколы `LayoutElement` и
  `LayoutSpecProviding`. Проверено на Linux тестовыми элементами: карточка профиля
  совпадает с Chromium до точки.
- `LayoutUIKit` — `UIView: LayoutElement` (измерение: своя раскладка → `sizeThatFits` при
  наличии intrinsic-размера → без содержимого), `LayoutView` (`layoutSubviews`,
  `sizeThatFits`, `intrinsicContentSize` из раскладки), `applyLayoutSpec()` и
  `layoutSpecSize(fitting:)` для ячеек и чужих классов.
- `LayoutAppKit` — то же для `NSView`; `LayoutNSView` перевёрнут (`isFlipped`), в
  неперевёрнутом родителе координата y отражается. Тесты `LayoutAdapterTests` выполняются
  только на macOS.

Не сделано: `hidden`/`invisible`, токены отступов, `from:`, `Breakpoint`, встраивание нод
(`addSubnode`), базовая линия.

## Диагностика

**Статус: принято в обсуждении.**

- Диагностика (что-то пошло не так: отклонённая раскладка, дубликат id, `Breakpoint` без
  определённой ширины) и трассировка (поузловые measure/place) — раздельно. Диагностика
  включена в Debug по умолчанию, трассировка — только по запросу, с фильтром по области и
  элементу.
- Движок не печатает: диагностика возвращается в результате (как `duplicateIDs`),
  трассировка — через необязательный записывающий объект в контексте, ничего не стоящий,
  когда его нет.
- Куда выводить (stdout, `os.Logger`, signposts), решает адаптер.
- По умолчанию — одна строка-сводка на проход вместо строки на узел. Поля `host`/`gen`/`#id`
  сохраняются.

## Решено

- **Код v22 — отдельный пакет** со своим `Package.swift` в `v22/`. Он не затрагивает API
  baseline и проверки Trellis и собирается независимо. **Согласовано.**
- **Старый движок не чинится.** Дефекты #95–#106 остаются «открыт» в Trellis и
  закрываются новым движком на этапе E1. **Согласовано.**

## Открыто
- Имя: в модуле `Layout` v22 движок может снова называться `FlexboxEngine` (D11 Trellis);
  конфликта нет — это другой модуль.
- Контракт измерения листа (три запроса) и его связь с `ContentMeasurer`.
