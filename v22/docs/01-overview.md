# Обзор и принципы

## Зачем v22

Trellis (этап 1–6) доказал конвейер: живое дерево нод на MainActor, иммутабельный
`Sendable`-снимок, flex-раскладка в фоне с отменой, один платформо-нейтральный рендер в
`CALayer`. Этот фундамент сохраняется.

Упираемся мы в **гибкость описания раскладки** и в **связанность систем**:

1. **Builder без ограничения размера** (D03). `arrangeSubnodes()` не знает ширину —
   адаптивную вёрстку «узко → колонка, широко → строка» не выразить.
2. **Закрытый словарь.** `Leaf`/`Row`/`Column`/`Overlay` и пять модификаторов
   (`grow`, `size`, `align`, `margin`, `offset`). Нет center, ratio, background, spacer,
   wrap; собственный контейнер написать нельзя — неизвестный `Arrangement` тихо
   становится пустым контейнером.
3. **Контейнер DSL = настоящая нода.** Каждый вложенный `Row`/`Column` порождает
   implicit wrapper-ноду со своим `CALayer` (D15: по замеру C30 это +37 % слоёв). Ради
   этих wrapper'ов существуют позиционные ключи D06, правила владения D05 и трёхслойная
   композиция стиля D12.
4. **Лишняя церемония.** `Leaf(node)` вокруг каждой ноды, параметры контейнера в `init`.
5. **Системы сплетены.** Раскладка знает только `Node`; нельзя взять flex-движок и
   разложить им обычные `UIView`.
6. **Ручная реактивность.** Экран сам сравнивает показанное с новым состоянием, сам
   кэширует дочерние ноды по id модели и сам зовёт `markArrangementDirty()`.

## Принципы v22

| # | Принцип | Статус |
|---|---|---|
| P1 | Каждая система — отдельный модуль, пригодный к использованию без остальных ([02-modules.md](02-modules.md)) | согласовано |
| P2 | Модель Texture: подкласс ноды, дочерние ноды создаются в `init` и хранятся в свойствах, раскладка на них только ссылается | согласовано |
| P3 | Контейнеры раскладки — только описание геометрии, как `ASLayoutSpec`: не ноды и не слои | согласовано |
| P4 | Модификаторы (`.flex`, `.padding`, `.size`) — параметры места в родителе, в ноду не записываются | согласовано |
| P5 | Одна раскладка для `Node`, `UIView`, `NSView` — один движок, разные адаптеры ([05-platform-adapters.md](05-platform-adapters.md)) | согласовано |
| P6 | Адаптивность по размеру контейнера — `Breakpoint` и адаптивные значения, решает движок ([04-conditionals-and-responsive.md](04-conditionals-and-responsive.md)) | согласовано |
| P7 | Flexbox совпадает с CSS, и это доказывается сравнением с браузером ([06-flexbox-conformance.md](06-flexbox-conformance.md)) | согласовано как цель |
| P8 | Короткие имена без суффикса `Node` ([07-naming.md](07-naming.md)) | согласовано |

## Что сохраняется из Trellis без изменений

- Живое дерево нод и нативные объекты — `@MainActor`; в фон уходят только
  `Sendable`-снимки. `@unchecked Sendable`, `nonisolated(unsafe)`, `@preconcurrency`
  запрещены.
- Отмена солвера — `throws -> LayoutResult`; пустой или частичный результат отменой не
  является (D09). Результат проверяется по generation/revision перед commit.
- Один платформо-нейтральный рендерер; UIKit/AppKit только в адаптерах.
- `NodeID` как runtime identity (D02).
- Поля диагностики `host`/`gen`/`#id`. Сам `Log.on` не переносится: движок не печатает,
  диагностика возвращается вызывающему, куда её выводить, решает адаптер
  ([10](10-layout-engine.md#диагностика)).
- Документация публичного API: `Ownership:`, `Isolation:`, `Errors:`, `Cancellation:`.

## Что пересматривается относительно Trellis

Для v22 эти решения Trellis перестают действовать. Для самого Trellis они остаются в силе.

| Решение Trellis | Что в v22 | Почему |
|---|---|---|
| D03 — Arrangement без constraint | Раскладка зависит от размера декларативно: `Breakpoint` и значения `from:` выбирает движок | адаптивная вёрстка без переноса расчёта на main |
| D05 — владение деревом Arrangement | Упрощается: нода из свойства, упомянутая в `layoutSpec()`, смонтирована; не упомянутая — снята, но жива | wrapper-нод больше нет |
| D06 — identity wrappers | Не нужно | контейнеры не являются нодами |
| D12 — композиция effective style | Сводится к «база ноды ⊕ параметры места от родителя» | нет implicit wrapper'ов и корневого контейнера-self |
| D15 — служебные контейнеры без слоя | Вопрос снят: у контейнеров слоёв нет по построению | P3 |
| D14 — источник состояния | Открыто, см. [08-open-questions.md](08-open-questions.md#состояние-и-реактивность) | обсуждение ещё не проводилось |
