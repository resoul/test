# Условия и адаптивность

## Главное правило

**Статус: согласовано.**

> **`if` — выбор по данным. `Breakpoint` — выбор по размеру.**

| | `if` / `switch` | `Breakpoint`, `from:` |
|---|---|---|
| Когда вычисляется | при построении раскладки, на main | движком во время расчёта, в фоне |
| Что знает | состояние, модель, environment | ширину, выделенную контейнеру |
| Чего не знает | ширину | модель |

## Инструменты

### 1. Обычный Swift внутри контейнеров

**Статус: согласовано.**

`if`/`else`, `switch` по enum, `if let`, `for`. Опциональная нода как элемент пропускается
при `nil`.

```swift
FlexContainer(.row) {
    avatar
    badge                 // Image? — nil означает «элемента нет»
    FlexContainer(.column) {
        title
        if showsHandle { subtitle }
    }
    .flex(grow: 1)
    if !isMe { follow }
}
```

После смены `showsHandle` владелец сообщает, что раскладка изменилась; `subtitle`
снимается с экрана и возвращается той же нодой.

### 2. `layoutSpec()` — обычная функция

**Статус: согласовано.**

```swift
override func layoutSpec() -> Layout {
    guard let user else { return placeholderLayout }
    let compact = environment.sizeClass == .compact
    return FlexContainer(compact ? .column : .row) { … }
}
```

`guard` внутри builder'а запрещён языком; здесь он доступен, потому что builder действует
только внутри скобок контейнера. Условия по environment (size class, Dynamic Type,
ориентация) — аналог CSS media queries — пишутся именно так.

### 3. Видимость

**Статус: согласовано.**

| | Место в раскладке | Нода смонтирована | Когда нужно |
|---|---|---|---|
| `if cond { x }` | нет | нет | элемента по смыслу нет |
| `x.hidden(cond)` — CSS `display: none` | нет | да | исчезновение с анимацией: нода ещё на экране |
| `x.invisible(cond)` — CSS `visibility: hidden` | да | да | ничего не должно прыгать: спиннер в кнопке, резерв под бейдж |

### 4. Условный модификатор

**Статус: согласовано** (включить, с рекомендацией не злоупотреблять).

```swift
title.if(isHighlighted) { $0.padding(16).alignSelf(.center) }
```

В SwiftUI это антипаттерн (ломает identity view). В v22 он **безопасен**: раскладка —
значение, пересобираемое на каждом проходе, identity ноды держит свойство класса.

Рекомендация пользователю: для одного параметра — значение (`.padding(compact ? 8 : 16)`);
модификаторы принимают опционалы (`.padding(nil)` — ничего не делать); `.if` — когда
условно применяется несколько модификаторов. Цепочек `.if … .else` нет.

### 5. `Breakpoint` — смена структуры по размеру

**Статус: согласовано.**

```swift
override func layoutSpec() -> Layout {
    Breakpoint(minWidth: 360) {
        FlexContainer(.row) { avatar.size(48); texts; follow }       // широко
    } otherwise: {
        FlexContainer(.column) { avatar.size(64); texts; follow }    // узко
    }
}
```

- Аналог CSS **container queries**, а не media queries: решает ширина, выделенная этому
  контейнеру. Карточка ведёт себя одинаково в узкой колонке iPad и на узком iPhone.
- Обе ветки описаны заранее, выбирает движок в фоне; после commit монтируются ноды
  выбранной ветки.
- Нода, присутствующая в обеих ветках (`avatar`), — одна и та же нода, которая
  переезжает. Смену брейкпоинта можно анимировать как перемещение.

**Правило неопределённой ширины** (как `container-type: inline-size` в CSS): `Breakpoint`
смотрит только на ширину, данную снаружи. Если снаружи ширина не определена (например,
flex-элемент без `grow` в строке, чей размер зависит от содержимого), возникает круговая
зависимость «ветка ↔ ширина». Тогда берётся ветка `otherwise`, и это пишется в лог через
`Log.on`, а не угадывается. **Статус правила: предложено.**

Ветки больше двух (`minWidth: 360`, `minWidth: 600`, …) — **открыто**: вложенные
`Breakpoint` или список порогов.

### 6. Адаптивные значения — смена параметра по размеру

**Статус: согласовано.**

```swift
FlexContainer(.row) { … }
    .gap(8)
    .gap(16, from: 600)       // от 600 pt ширины контейнера
    .padding(12)
    .padding(24, from: 600)
```

Как `md:p-6` в Tailwind. Решает движок по той же ширине контейнера, что и `Breakpoint`.

> Меняется **структура** → `Breakpoint`. Меняется **число** → `from:`.

### 7. Кэш нод для динамических списков

**Статус: согласовано.**

Ноды в свойствах работают для фиксированного набора. Для «N элементов из модели» нужен
кэш по id модели: создаёт ноду для нового id, переиспользует существующую, отдаёт ушедшие.

```swift
private let rows = NodeCache<Item.ID, ItemRow> { ItemRow() }

FlexContainer(.column) {
    for item in items {
        rows[item.id].update(item)      // update возвращает саму ноду
    }
}
```

Заменяет ручной словарь `itemRows[item]` из Trellis-сценария S32. Identity переживает
перестановки. Политика освобождения ушедших нод (сразу, после commit, по лимиту) —
**открыто**.

Отдельного типа `ForEach` нет: `for` + `NodeCache` покрывают этот случай.

### 8. Пустой контейнер

**Статус: согласовано** (включить).

По CSS контейнер без детей сохраняет `padding` и занимает место. `.collapsesWhenEmpty()` —
аналог `:empty { display: none }` — убирает пустую плашку.

## Чего нет сознательно

- Тип `ForEach` — см. п. 7.
- Цепочки `.if … .else` — для этого обычный `if` снаружи.
- Условия по размеру в `if` — размер известен только движку; для этого `Breakpoint` и
  `from:`.

## Появление и исчезновение с анимацией

**Статус: открыто.** `.transition(.opacity)` на элементе для `if`/`hidden`/смены
брейкпоинта; опирается на анимации и transitions Trellis (планы 5 и M10). Обсуждается
отдельно.
