# Скриншотный gate: что нужно для побайтной воспроизводимости

`Scripts/check_screenshots.py` собирает Playground-macOS, экспортирует каждую сцену дважды
(`<name>.png`, `<name>_overlay.png`) и сравнивает побайтно с `docs/validation/screenshots`.
За день работы гейт ловил регрессии трижды и трижды ловил собственную недетерминированность;
вот что её убирает (см. дефекты #7, #8, #17 в [defects.md](../defects.md)):

| Источник шума | Мера |
|---|---|
| Захват до первого commit на холодном старте | ожидание `root.calculatedFrame != nil` вместо фиксированной задержки |
| Хост suspend'ит координатор, пока окно не key; потеря фокуса посреди экспорта | ожидание периодически возвращает окну key-статус; сцена без commit печатает WARNING |
| Масштаб экрана: на 1× внешнем дисплее раскладка округляется иначе и кадр вдвое меньше | `TrellisHostView.hostScaleOverride = 2` на время экспорта (public API; `nil` — следовать экрану) |
| Глобальные `NodeID` в подписях overlay | известная стоимость (#11): правка ранней сцены перебазирует overlay-референсы следующих |
| Динамические сцены (S15, S20): на занятой машине первый commit приходил позже первого тика сессии, захватывалась фаза 1 (#18) | `ScenarioSession.firstTickDelay` — 60 s на время экспорта; захват всегда фаза 0 |
| Гонка инвалидации с выходом worker'а: координатор замирал навсегда (#20 — дефект продукта; сцена захватывалась пустой с WARNING «never committed») | исправлено в `LayoutScheduler` |
| Stale `suspend` bridge'а после предыдущего mount'а (#21 — дефект продукта): binding paused, новый координатор коммитит без состояния | исправлено: `attach` начинает mount активным |
| Потеря key-статуса в момент `bindState` (S20): binding доставлял модель после первого flush (#19 — дефект продукта, не гейта) | исправлено в bridge: bindings резюмируются синхронно до координатора |

Обновление референсов — только `--update --review-note <tracked doc>`; hosted CI пока
пропускает гейт (`--skip-screenshots`) до C27 — не проверено, что runner рендерит так же.
