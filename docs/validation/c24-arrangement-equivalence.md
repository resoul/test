# C24 — Эквивалентность и сценарии Arrangement на устройствах

Дата: 2026-09-11. Финальная приёмка майлстоуна **M5 (Arrangement)**.

## Цель и задачи

Подтвердить на практике эквивалентность декларативного слоя `Arrangement` (`Row`, `Column`, `Overlay`, `Leaf`, `@ArrangementBuilder`) императивному построению дерева нод:
1. Полное совпадение рассчитанной геометрии (координаты и размеры) для сложных сценариев вложенности (S10) и динамических мутаций (S15).
2. Чистый сброс эффективных стилей при снятии модификаторов (`.margin(...)`, `.grow(...)`).
3. Корректный жизненный цикл условных обёрток (`conditional wrapper`) — переиспользование и очистка слоёв без затрагивания вложенных пользовательских `Leaf`.
4. Сохранение `NodeID` и непрерывность инстансов `CALayer` при переупорядочивании элементов (`reorder`).
5. Отсутствие утечек памяти и слоёв при стрессовой циклической перестройке дерева (`stress churn`).
6. Интеграция сценариев в `Playground` для macOS, iOS и tvOS с проверкой сборки всех таргетов.

## Реализованные тесты

### 1. Эквивалентность геометрии S10 (`ArrangementEquivalenceTests.swift`)
- **Императивное дерево:** 4 уровня вложенности контейнеров (`level1`, `level2`, `level3` с `padding: 12`) и фиксированный `leaf` (100×64).
- **Декларативный подкласс (`S10ArrangedCard`):** вложенные `Column(padding:)` с `Leaf(leaf)` внутри `arrangeSubnodes()`.
- **Результат:** 
  - `rootSub.calculatedFrame == rootImp.calculatedFrame`
  - `level1Sub.calculatedFrame == level1Imp.calculatedFrame`
  - `level2Sub.calculatedFrame == level2Imp.calculatedFrame`
  - `level3Sub.calculatedFrame == level3Imp.calculatedFrame`
  - `leafSub.calculatedFrame == leafImp.calculatedFrame`
  - Рассчитанные координаты и размеры совпадают пиксель в пиксель по всем семантическим путям.

### 2. Динамические переходы и сохранение `NodeID` (S15)
- Проверены три фазы:
  - Фаза 1: отсутствие `transient` — геометрия `stable` идентична императивной версии.
  - Фаза 2: появление `transient` — точное совпадение размещения обоих элементов с императивной версией; `transient.id` сохраняется.
  - Фаза 3: удаление `transient` — возврат к исходной раскладке; узел не уничтожается (`isDisposed == false`) и сохраняет свой идентификатор для последующего повторного монтирования.

### 3. Снятие модификаторов (Removal Modifiers)
- Проверено последовательное снятие модификаторов `.margin(...)` и `.grow(1)`:
  - Снятие `.margin(...)` сбрасывает отступы до 0, возвращая полную доступную ширину.
  - Снятие `.grow(1)` возвращает ноду к базовому размеру `node.style.width` (40 pt).
  - Базовые стили (`node.style`) остаются нетронутыми (D04).

### 4. Условные обёртки и переупорядочивание Leaf
- При `wrapInContainer = true` создаётся контейнер-обёртка; при `false` обёртка утилизируется (`isDisposed == true`), а пользовательские `Leaf` перемещаются обратно к родителю без вызова `dispose()`.
- При `isReversed = true` порядок расположения в `subnodes` и вертикальные позиции в раскладке меняются местами, сохраняя стабильный `NodeID`.

### 5. Стабильность `CALayer` и отсутствие утечек (`ArrangementLayerIdentityTests.swift`)
- **Повторный resolve без изменений:** `renderer.layer(for: node.id)` возвращает в точности тот же инстанс `CALayer` (`===`), подтверждая отсутствие пересоздания слоёв при повторных кадрах.
- **Удаление обёртки:** слой удалённого wrapper'а корректно удаляется из иерархии `CALayer` и отслеживаемого реестра, а слои дочерних `Leaf` безопасно перепривязываются к родительскому слою.
- **Стресс-тест (40 циклов):** чередование оборачивания, реверсирования и добавления/удаления элементов не оставляет висячих слоёв — количество зарегистрированных слоёв строго равно количеству живых нод в дереве.

## Обновления в Playground

1. **`Playground/Shared/Scenarios/S10_Nesting.swift`:**
   - Предоставлены оба варианта: `makeImperative` и `makeSubclass`.
   - `make` по умолчанию использует декларативный `S10ArrangedCard`, демонстрируя эквивалентную визуализацию с цветными промежуточными уровнями.
2. **`Playground/Shared/Scenarios/S15_DynamicMutation.swift`:**
   - Превращён в интерактивный `S15ArrangedContainer` с циклическим переключением фаз каждую секунду:
     - Фаза 0: базовое состояние (`stable` + `transient`).
     - Фаза 1: добавление модификатора `.margin(...)`.
     - Фаза 2: условное оборачивание в `Row` и реверсирование порядка (`isReversed = true`).
     - Фаза 3: удаление обёртки и скрытие `transient`.
3. **Кроссплатформенная сборка:**
   - Таргеты `Playground-macOS`, `Playground-iOS` и `Playground-tvOS` успешно собираются и валидируются через `xcodebuild`.
