# Условия и адаптивность

## Главное правило

**Статус: согласовано.**

> **`if` — выбор по данным. `Breakpoint` — выбор по размеру.**

| | `if` / `switch` | `Breakpoint`, `from:` |
|---|---|---|
| Когда вычисляется | при построении раскладки, на main | движком во время расчёта, в фоне |
| Что знает | состояние, модель, environment | ширину, выделенную контейнеру |
| Чего не знает | ширину | модель |

## Инструменты

### 1. Обычный Swift внутри контейнеров

**Статус: согласовано.**

`if`/`else`, `switch` по enum, `if let`, `for`. Опциональная нода как элемент пропускается
при `nil`.

```swift
FlexContainer(.row) {
    avatar
    badge                 // Image? — nil означает «элемента нет»
    FlexContainer(.column) {
        title
        if showsHandle { subtitle }
    }
    .flex(grow: 1)
    if !isMe { follow }
}
```

После смены `showsHandle` владелец сообщает, что раскладка изменилась; `subtitle`
снимается с экрана и возвращается той же нодой.

### 2. `layoutSpec()` — обычная функция

**Статус: согласовано.**

```swift
override func layoutSpec() -> LayoutSpec? {
    guard let user else { return placeholderLayout }
    let compact = environment.sizeClass == .compact
    return FlexContainer(compact ? .column : .row) { … }
}
```

`guard` внутри builder'а запрещён языком; здесь он доступен, потому что builder действует
только внутри скобок контейнера. Условия по environment (size class, Dynamic Type,
ориентация) — аналог CSS media queries — пишутся именно так.

### 3. Видимость

**Статус: согласовано.**

| | Место в раскладке | Нода смонтирована | Когда нужно |
|---|---|---|---|
| `if cond { x }` | нет | нет | элемента по смыслу нет |
| `x.hidden(cond)` — CSS `display: none` | нет | да | исчезновение с анимацией: нода ещё на экране |
| `x.invisible(cond)` — CSS `visibility: hidden` | да | да | ничего не должно прыгать: спиннер в кнопке, резерв под бейдж |

### 4. Условный модификатор

**Статус: согласовано** (включить, с рекомендацией не злоупотреблять).

```swift
title.if(isHighlighted) { $0.padding(16).alignSelf(.center) }
```

В SwiftUI это антипаттерн (ломает identity view). В Espalier он **безопасен**: раскладка —
значение, пересобираемое на каждом проходе, identity ноды держит свойство класса.

Рекомендация пользователю: для одного параметра — значение (`.padding(compact ? 8 : 16)`);
модификаторы принимают опционалы (`nil` — ничего не делать: `.padding(isCompact ? nil : 16)`); `.if` — когда
условно применяется несколько модификаторов. Цепочек `.if … .else` нет.

**Реализовано (2026-09-25):** `.if(_:_:)` в `LayoutCore`; все модификаторы с одним значением
принимают опционал, `nil` возвращает спеку без изменений: `.padding(isCompact ? nil : 16)`,
`.gap(optionalGap)`, `.alignSelf(alignment)`. У `padding`/`margin`/`gap` два типа значения —
число и шаг шкалы (`.s4`), поэтому голый литерал `.padding(nil)` неоднозначен и не
компилируется; он и не нужен — ничего не делает. Тернарник и переменная типа `Double?` /
`Spacing?` выбирают перегрузку сами.

### 5. `Breakpoint` — смена структуры по размеру

**Статус: согласовано.**

```swift
override func layoutSpec() -> LayoutSpec? {
    Breakpoint(from: .sm) {
        FlexContainer(.row) { avatar.size(48); texts; follow }       // широко
    } otherwise: {
        FlexContainer(.column) { avatar.size(64); texts; follow }    // узко
    }
}
```

- Порог записывается тем же `from:`, что и в адаптивных значениях (п. 6), числом или
  именем (`from: 400` / `from: .sm`). Единое слово вместо прежнего `minWidth:` —
  **согласовано** (2026-09-25).
- Аналог CSS **container queries**, а не media queries: решает ширина, выделенная этому
  контейнеру. Карточка ведёт себя одинаково в узкой колонке iPad и на узком iPhone.
- Обе ветки описаны заранее, выбирает движок в фоне; после commit монтируются ноды
  выбранной ветки.
- Нода, присутствующая в обеих ветках (`avatar`), — одна и та же нода, которая
  переезжает. Смену брейкпоинта можно анимировать как перемещение.

**Правило неопределённой ширины** (как `container-type: inline-size` в CSS): `Breakpoint`
смотрит только на ширину, данную снаружи. Если снаружи ширина не определена (например,
flex-элемент без `grow` в строке, чей размер зависит от содержимого), возникает круговая
зависимость «ветка ↔ ширина». Тогда берётся ветка `otherwise`, а не угадывается. Движок
так и делает: без определённой ширины варианты по ширине не применяются, а узел попадает
в `LayoutResult.variantsWithoutWidth` и в `widthless=` отчёта прохода ноды (реализовано
2026-09-25). **Статус правила: предложено.**

Ветки больше двух — **реализовано (2026-09-27): список порогов; имена — предложено.**

```swift
Breakpoint([
    .from(.lg) { FlexContainer(.row) { sidebar; list; details } },
    .from(.md) { FlexContainer(.row) { sidebar; list } },
]) {
    FlexContainer(.column) { list }
}
```

- Каждая ветка (`BreakpointCase.from(_:_:)`) показана от своего порога до порога следующей
  более широкой, последняя (`otherwise`) — ниже всех; порядок в списке не важен. Нода в
  нескольких ветках — одна нода, которая переезжает. Без определённой ширины — `otherwise`,
  как и у двух веток.
- В движке каждая ветка получает свой диапазон ширин [от, до): `display` — `none` вне его,
  `flex` внутри (правила `from:`, как у адаптивных значений); `hidden` самого элемента
  по-прежнему скрывает его и внутри диапазона.
- `Breakpoint`, стоящий прямо в ветке другого, раскрывается на её месте, а его диапазоны
  пересекаются с диапазоном ветки. Раньше (#193) так вложенный `Breakpoint` показывал свои
  ветки без учёта внешнего порога — при ширине 500 были видны и `wide`, и `middle`.
- Переходы (`transition`) работают и при смене ветки: нода уходящей ветки скрывается, новая
  показывается ([появление и исчезновение](#появление-и-исчезновение-с-анимацией)).

Проверено (2026-09-27): 4 теста `LayoutCore` — три ветки на трёх ширинах (и в обратном
порядке списка; одна и та же нода переезжает), без ширины — `otherwise`, `Breakpoint` в
ветке другого — двухветочного (#193) и многоветочного (порог внутреннего шире внешней
ветки); прежние тесты `Breakpoint` проходят; 5 намеренных поломок — каждую ловит тест. Демо:
карточка профиля — три ветки (колонка, строка от 460, строка с кнопкой справа от 760);
вживую на iPad Pro 13" Simulator — широкая ветка (`simctl`), на iPhone 17 Simulator —
колонка.

### 6. Адаптивные значения — смена параметра по размеру

**Статус: согласовано.**

```swift
FlexContainer(.row) { … }
    .gap(8)
    .gap(16, from: .md)       // от 600 pt ширины контейнера
    .padding(12)
    .padding(24, from: .md)
```

Как `md:p-6` в Tailwind. Решает движок по той же ширине контейнера, что и `Breakpoint`.

> Меняется **структура** → `Breakpoint`. Меняется **число** → `from:`.

#### Именованные пороги

**Статус: имена согласованы; значения — предложено** (стартовая точка, проверить на
экранах Playground).

Порог принимает и число, и имя: `from: 600` и `from: .md` равноправны, сырые числа не
запрещены.

| Имя | pt | Что обычно так широко |
|---|---|---|
| `.sm` | 400 | большой iPhone в портрете, карточка в широкой колонке |
| `.md` | 600 | iPhone в ландшафте, узкая колонка iPad |
| `.lg` | 840 | iPad в портрете, окно Mac |
| `.xl` | 1200 | iPad в ландшафте, большое окно Mac |
| `.xxl` | 1600 | tvOS, полноэкранный Mac |

Значения от `.md` и выше взяты по порогам Material 3 (1 dp ≈ 1 pt); `.sm` добавлен для
компонентного уровня — карточек в колонках.

Почему размеры, а не устройства (`phone`/`tablet`/`laptop`): порог сравнивается с шириной
**контейнера**, а не экрана. Карточка шириной 320 pt в боковой колонке iPad — не
«tablet», и имя-устройство там вводило бы в заблуждение. `compact`/`regular` не
используются, чтобы не путать с size class Apple — тот описывает окно и в Espalier проверяется
через environment и `if` (п. 2).

Свои пороги приложение добавляет через `extension` с именем по смыслу:

```swift
extension BreakpointWidth {
    static let sidebar: Self = 280
}
```

Переопределение значений встроенных порогов для всего приложения (например, `.md = 640`
через тему) — **открыто**: технически возможно, потому что имена превращаются в числа при
подготовке снимка на main, но пока не нужно.

Числовые отступы (`8`, `12`, `24`) тоже можно называть — это токены темы, см.
[09-theme.md](09-theme.md).

### 7. Кэш нод для динамических списков

**Статус: согласовано.**

Ноды в свойствах работают для фиксированного набора. Для «N элементов из модели» нужен
кэш по id модели: создаёт ноду для нового id, переиспользует существующую, отдаёт ушедшие.

```swift
private let rows = NodeCache<Item.ID, ItemRow> { ItemRow() }

FlexContainer(.column) {
    for item in items {
        rows[item.id].update(item)      // update возвращает саму ноду
    }
}
```

Заменяет ручной словарь `itemRows[item]` из Trellis-сценария S32. Identity переживает
перестановки. **Реализовано (2026-09-24):** `NodeCache<Key, Item>` в `Nodes`.

**Политика освобождения — согласовано (2026-09-27).**

- **По умолчанию (вариант A, реализован):** нода, которую раскладка перестала запрашивать,
  отпускается. Точно: кэш отпускает неиспрошенные ноды при первом обращении к нему в новом
  проходе (проходы различает счётчик проходов всех хостов). Если к кэшу больше не
  обращаются, автоматической очистки нет — ноды остаются до следующего обращения. Это
  поведение закреплено как контракт, а не как побочный эффект.
- **Состояние, которое должно пережить уход строки с экрана**, хранится в модели по
  идентификатору: введённый текст, выбор, раскрытие раздела. Кэш не решает, сохранится ли
  действие пользователя; сохранность состояния ноды при отпускании не гарантируется.
- **Запас последних отпущенных нод (вариант C) допускается архитектурно**, реализуется при
  измеренной пользе. Его контракт: лимит считает только неиспользуемые ноды (видимые в него
  не входят); удержание в запасе — не присутствие на экране (уход из дерева всё равно
  завершает задачи показа: загрузки, таймеры, отслеживание экрана); приложение может
  очистить запас явно; ноду из запаса могут вытеснить в любой момент.
- **Обязательного режима «держать, пока ключ есть в данных» (вариант B) нет.**
- Для картинок нужен кэш изображений (`ImageCache`), а не удержание нод.

Отдельного типа `ForEach` нет: `for` + `NodeCache` покрывают этот случай.

### 8. Пустой контейнер

**Статус: согласовано** (включить).

По CSS контейнер без детей сохраняет `padding` и занимает место. `.collapsesWhenEmpty()` —
аналог `:empty { display: none }` — убирает пустую плашку.

**Реализовано (2026-09-25).** Пустота считается по списку элементов, как в CSS: ложный `if` и
`nil` элемента не добавляют ничего, скрытый (`hidden`) элемент — есть, и контейнер остаётся.
На элементе (ноде со своей `layoutSpec()`) модификатор ничего не делает.

## Чего нет сознательно

- Тип `ForEach` — см. п. 7.
- Цепочки `.if … .else` — для этого обычный `if` снаружи.
- Условия по размеру в `if` — размер известен только движку; для этого `Breakpoint` и
  `from:`.

## Появление и исчезновение с анимацией

**Статус: реализовано (2026-09-27); имена — предложено.** У ноды — `transition`
(`Transition`, модуль `Nodes`): как она приходит на экран и уходит с него в анимированном
изменении — `if` в `layoutSpec()`, сторона `Breakpoint`, `hidden`/`invisible`. Без перехода
нода проявляется и угасает, как раньше.

```swift
badge.transition = .scale.combined(with: .opacity)

override func layoutSpec() -> LayoutSpec? {
    FlexContainer(.column) {
        if showsToast.value { toast.transition(.move(edge: .bottom)) }
    }
}

withAnimation { showsToast.value.toggle() }
```

- Переходы: `.opacity` (по умолчанию), `.identity` (сразу, даже в анимированном изменении),
  `.scale` и `.scale(_:anchor:)`, `.move(edge:)` (на свой размер к краю), `.offset(x:y:)`,
  `.slide` (из ведущего края, к заднему), `.push(from:)` (с края с проявлением, к
  противоположному с угасанием), `.rotation(degrees:anchor:)`, `.flip(_:)` (карточка
  переворачивается ребром, в перспективе), `.pop` (из меньшего размера пружиной).
- Составление: `.combined(with:)` (прозрачности и масштабы умножаются, сдвиги и повороты
  складываются), `.asymmetric(insertion:removal:)`, `.animation(_:)` — своя анимация перехода
  вместо анимации изменения. Без анимации изменения нода приходит и уходит сразу.
- Своё: `Transition(insertion:removal:)` из `Transition.Effect` — прозрачность, масштаб по
  осям, поворот, переворот по осям, сдвиг в точках и в долях своего размера, точка опоры.
- Ведущий и задний края, опора и переворот вокруг вертикали — по направлению раскладки: в
  RTL ведущий край справа.
- Рисует `LayerRenderer`: сдвиг, масштаб и поворот — трансформация слоя (поверх
  `appearance.scale`), рамка ноды не меняется. Уходящий слой прозрачен в модели и держит
  анимацию прозрачности — хотя бы от значения к нему же, для переходов без угасания: так он
  не виден после конца анимации и убирается при следующей отрисовке, как угасающий раньше.

Проверено (2026-09-27): 6 тестов модели (Linux-совместимые) — края, сочетания, асимметрия,
переворот, `transition(_:)` у ноды; 10 тестов рендерера на Mac — масштаб без угасания, сдвиг
с ведущего края в LTR и RTL, уход к краю и невидимость после, `.identity` сразу, асимметрия,
своя анимация перехода (пружина), скрытие и показ через переход (без проявления у
возвращённого), переход, заданный в `layoutSpec()`, точка опоры масштаба (LTR и RTL),
поворот и переворот; 9 намеренных поломок — каждую ловит тест. Демо — раздел «Transitions»:
кнопка на каждый переход убирает карточку и возвращает её. UI-тест iOS-демо на iPhone 17
Simulator: «Flip» убирает карточку и возвращает на прежнее место. Глазами на iPhone 17
Simulator (анимация временно растянута до 4 с): посреди «Flip» карточка стоит ребром — узкая
полоса в перспективе, в конце «Turn» — чуть повёрнута по часовой стрелке. На устройствах —
нет доступа.
