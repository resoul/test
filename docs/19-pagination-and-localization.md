# Подгрузка страниц и локализация

2026-10-09. Две вещи из Trellis и Weave, перенесённые не копированием, а по замыслу: старый код привязан к
`CollectionSnapshot` и Flux (подгрузка) и к окружению Weave (локализация).

## 1. Подгрузка страниц

Список просит следующую страницу сам, когда конец списка подошёл к окну. Живёт в `Nodes`: `Pagination.swift` (чистый
автомат и значения), `LazyStack` (привязка к окну и прокрутке), `Table` (те же свойства сквозь неё).

### Как пользоваться

```swift
stack.pagination = PaginationPolicy(pageSize: 20)
stack.loadMore = { request in                       // главный актор; request.loadedCount — сколько уже есть
    let page = try await api.messages(after: request.loadedCount, limit: request.pageSize ?? 20)
    stack.items += page.items                       // страницу добавляют до возврата
    if page.isLast { stack.reachedEnd = true }
}
// подвал по состоянию:
footer.text = switch stack.pageLoadState { case .loading: "…"; case .failed: "Повторить"; case .endReached: ""; case .idle: "" }
retryButton.onTap = { stack.retryLoadingPage() }
// новый поиск:
stack.items = []; stack.restartPagination()
```

- **Когда просит** (`PaginationTrigger`): по умолчанию, когда после окна осталось не больше двух длин окна
  (`.remainingViewportLengths(2)`); либо когда после последней видимой строки осталось не больше N элементов
  (`.remainingItems(N)`). Расстояние считается от последней видимой строки, а не от первой: так работает при разной высоте
  строк и в сетке (`lanes`). Пустой список просит первую страницу сразу.
- **Решение принимает `PaginationGate`** — значение без ввода-вывода. Ответы: `request`, `duplicate`, `notNeeded`,
  `endReached`, `awaitingRetry`, `noProgress`, `automaticLimit`. Один запрос на версию `items` (версия растёт при каждом
  присваивании), пока страница в пути — новых нет.
- **Ошибка** (`throw` из `loadMore`) — состояние `.failed`, причина в `pageLoadError`; сам список больше не просит, пока
  не вызвано `retryLoadingPage()` (оно не смотрит на расстояние: человек попросил).
- **Страница, которая ничего не добавила**, не даёт списку просить бесконечно: пока человек не прокрутил, нового запроса нет.
  Страница, что пришла позже возврата замыкания, это замечает (`itemsChanged`).
- **Предел подряд без прокрутки** (`maximumAutomaticPages`, 3): список короче окна не будет просить без конца.
  Прокрутка начинает счёт заново. Прокруткой считается сдвиг окна по списку больше чем на полпункта.
- **Отмена.** Уход списка с экрана отменяет страницу в пути (`Task.cancel`) и не считается ошибкой; вернулся — просит
  снова, если конец близко. `restartPagination()` отменяет страницу, забывает ошибку и конец.
- **`Table`**: те же `pagination`, `loadMore`, `reachedEnd`, `pageLoadState`, `pageLoadError`, `retryLoadingPage()`,
  `restartPagination()`; `PageRequest.loadedCount` считает строки, а не заголовки секций.

### Что изменено по сравнению с Trellis

- Нет `CollectionSnapshot` с ревизиями и `loadState`: роль ревизии играет версия `items`, роль `loadState` — свойства списка.
- Страницу грузит `async`-замыкание, а не эффект Flux; завершение — возврат замыкания, ошибка — `throw`.
- **Дефект в старом коде** (#225): после страницы без прироста `userDidScroll` снимал `stalled`, но `requestedRevision`
  оставался прежним, и автомат отвечал `duplicate` — прокрутка не возобновляла запросы, хотя комментарий обещал. Здесь
  `userDidScroll` снимает и то и другое, и это проверено (`aPageThatAddedNothingStopsTheListUntilItIsScrolled`).

### Проверено

подгрузка с `chunked`-источником и реальной сетью.

## 2. Локализация

Новый модуль `LocalizationCore` (только Foundation) и подключение к `Nodes`.

### Устройство

- **`LocalizedText`** — значение: ключ, таблица, текст по умолчанию (по умолчанию сам ключ), `count` (выбирает форму
  множественного числа и служит первым аргументом) и аргументы `%1$@`, `%2$@`… Пишется там, где создаётся узел, а
  разрешается там, где показывается: смена языка не требует создавать текст заново.
- **`LocalizationCatalog`** — строки по языку, таблице и ключу: `.text` или `.plural` (форма → строка). Идентификаторы
  языков сравниваются без учёта регистра и разделителя (`pt_BR` = `pt-br`). `LocalizationCatalog.loading(from: bundle)` читает
  `.strings` (текстовый формат и property list — то, во что Xcode собирает каталог строк) и `.stringsdict` (ключ с одним
  `%#@переменная@` и текстом вокруг; ключ с несколькими переменными пропускается, а не читается неверно).
  `LocalizationCatalog.main` — строки основного пакета, читаются при первом обращении.
- **`CatalogLocalizer`** (протокол `Localizer`): цепочка идентификаторов от точного к общему (`pt-BR`, `pt`; для
  `zh-Hans-CN` — `zh-hans-cn`, `zh-hans`, `zh-cn`, `zh`; берутся только части, названные в идентификаторе, потому что
  `Locale.language.script` дополняет вероятным письмом и добавил бы `pt-latn` каждому португальскому), потом
  `fallbackLanguages` (английский). Первый каталог с ключом отвечает. **Форму множественного числа выбирают правила языка,
  который ответил**, а не запрошенного: английскую строку, показанную украинцу, считают по-английски. Числа и даты пишутся для
  запрошенной локали. Нет ключа — текст по умолчанию и `ResolvedText.missing`; `onMissing` сообщает о каждом.
- **`PluralRules`** — правила CLDR для целых чисел: китайский, японский, корейский и ещё семь языков без форм; английский и
  родственные (`one`/`other`); французский и португальский (0 и 1 — `one`); русский, украинский, белорусский, польский
  (`one`/`few`/`many`); чешский, словацкий, хорватский, сербский, литовский, румынский; словенский, иврит, латышский,
  арабский (шесть форм). Остальные языки считаются как английский. `many` для круглых миллионов во французском, испанском,
  итальянском и португальском не моделируется.
- **Подстановки**: `%1$@`, `%@`, `%d`, `%ld`, `%lld`, `%u`, `%f` и `%.2f`, `%%`; числа и даты по локали. Подстановка без
  аргумента остаётся как написана.
- **`PseudoLocalizer`** — обёртка над любым локализатором: акценты, скобки `［…］`, удлинение на 30 %. Показывает строки,
  не прошедшие локализацию (они остаются обычными), и места, где более длинный язык не помещается.
- **`Locale.isRightToLeft`** — по данным языка, а не по списку.

### В узлах

`NodeHost.locale` и `NodeHost.localizer` (оба отслеживаются), `Node.locale`, `Node.localized(_:)`: прочитанные в `update()` или
`layoutSpec()`, они обновляют узел при смене языка или локализатора; смена локали заново раскладывает дерево, потому что
длины строк меняются. `Text(localized:)` и `Text.localizedText`. Адаптеры UIKit и AppKit берут локаль системы и обновляют её
по `NSLocale.currentLocaleDidChangeNotification`, **если приложение не поставило свою** (иначе оставляют её).

**Направление письма хост по локали не определяет:** `host.direction` ставят адаптеры по платформе. Приложение, которое
переключает язык на арабский внутри себя при системном левом направлении, направление не получит — это отдельная задача.

### Что изменено по сравнению с Weave

- Нет окружения Weave (`EnvironmentValues`) и Flux-канала `ActionPipe`: локаль — состояние хоста, слежение — `StateCore`.
- Множественное число не «один / остальное», а правила языка; правила берутся от ответившего языка.
- Загрузка из `.strings` / `.stringsdict`, цепочка регионов, таблицы, диагностика и отдельный псевдолокализатор.
- Определение направления — по данным языка, а не по списку из семи кодов.

### Проверено

`swift test` на Mac: `LocalizationCoreTests` (39: правила множественного числа по языкам, цепочка языков и направление,
поиск и откат, форма от ответившего языка, таблицы, подстановки и форматы чисел и дат по локали, чтение `.strings` в двух
форматах и `.stringsdict`, псевдолокализация), `NodesTests` (7: узел следует за языком и за локализатором, смена
локали раскладывает дерево, множественное число, отчёт о пропущенном ключе), `NodesRenderTests` (1: `Text`). Проверка поломкой:
правила множественного числа от запрошенной, а не ответившей локали, без раскладки при смене локали, без слежения за
локализатором, без запасных языков — каждая ловится.

**На iPhone 17 Simulator** (`LocalizationTests`, проба `LOCALIZATION_PROBE`): приложение, запущенное с `-AppleLanguages (ru)
-AppleLocale ru_RU`, показывает русский заголовок и все четыре русские формы «письмо / письма / писем / письмо» для 1, 3, 5, 21;
с `en_US` — английские формы; строка `locale:` показывает локаль, которую взял хост. **Находка:** язык приложения система выбирает
только из тех, что приложение объявило (`CFBundleLocalizations` или папки `*.lproj`): без этого `-AppleLanguages (ru)` оставляет
английский язык с регионом России (`en_RU`), и локализованный текст остаётся английским. Демо теперь объявляет `en` и `ru`
(`Demo/iOS/ExtraInfo.plist`, подмешан в созданный Info.plist). Любому приложению с этим пакетом нужно то же самое.

**Не проверено.** Смена языка системы в работающем приложении (уведомление `NSLocale.currentLocaleDidChangeNotification` и
обновление `host.locale` — не проверялись, проверен только язык при запуске); чтение собранного Xcode каталога строк (`.xcstrings`) из
настоящего приложения, только созданные в тесте пакеты; `.stringsdict` с несколькими переменными или `NSStringFormatSpecTypeKey`
не плюральным; языки, которых нет в списке правил (считаются как английский); дробные числа во множественном числе;
`Shell` не хранит языка на всё приложение: сменить его в нескольких окнах сразу можно только через `host.locale` каждого.
