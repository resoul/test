# Video: показ видео в дереве нод

**Статус: задача на реализацию, 2026-09-30.** Пользователь запросил компонент `Video`
по аналогии с существующим `Image`. Сначала нужен показ и базовое программное управление
видео; полноценный плеер с интерфейсом управления будет отдельной задачей позже.
Требование компонента, собственная placeholder-нода и улучшения раздела 4.1 приняты
пользователем; точные сигнатуры API и технические решения остаются предложениями. Код не реализован
в рамках этой записи. План CLI перенесён в `docs/17-project-cli.md`.

## 1. Результат и границы

`Video` размещается в layoutSpec, показывает локальное или сетевое видео, соблюдает
геометрию, обрезку и жизненный цикл дерева. Приложение управляет воспроизведением через
небольшой API и наблюдает состояние. Встроенной панели управления пока нет.

Отложить в отдельную задачу плеера: timeline и его жесты, полноэкранный режим,
Picture in Picture, выбор качества/аудиодорожек/субтитров, AirPlay UI, системные команды
Now Playing, плейлисты, реклама и DRM. Отсутствие собственного UI не отменяет необходимости
правильно обрабатывать паузу, звук, ошибки и освобождение ресурсов.

## 2. Что уже есть в проекте

- `Sources/NodesRender/Image.swift`: источник, contentMode, placeholder, наблюдаемая фаза,
  обработка mount/show/screen и отмена. Повторяем понятный стиль API, но не механизм
  декодирования изображений для каждого кадра видео.
- `Sources/NodesRender/ImageCache.swift`: специализированный кэш изображений. Видео
  автоматически в него не попадает.
- `Sources/Nodes/Embedded.swift`: EmbeddedNode и геометрия видимой части в NodeHost.
- `Sources/NodesUIKit/Embedded.swift`, `Sources/NodesAppKit/Embedded.swift`: платформенные
  виды с обрезкой в рамке ноды, создание и удаление по жизненному циклу дерева.
- StateCore обеспечивает наблюдение состояния на MainActor; LayoutCore остаётся чистым
  и ничего не знает про AVFoundation.

Вложенные виды сейчас показываются поверх рисованных слоёв. Поэтому произвольное
чередование видео, текста и оверлеев нельзя считать автоматически решённым. Прототип
должен проверить порядок, clipping, скругления, прозрачность и преобразования отдельно.

## 3. Архитектура

Предпочтительный первый путь: `Video` как EmbeddedNode; UIKit/AppKit-вид содержит
платформенную поверхность видео. Основа Apple-реализации — AVFoundation: AVPlayer для
воспроизведения и AVPlayerLayer для показа. Это направление проверяется на целевых SDK:
[AVPlayer](https://developer.apple.com/documentation/avfoundation/avplayer),
[AVPlayerLayer](https://developer.apple.com/documentation/avfoundation/avplayerlayer).

Не пропускать кадры через CGContext/CGImage общего LayerRenderer. Декодирование и показ
кадров принадлежат медиа-подсистеме, дерево управляет расположением поверхности.

Предлагаемое размещение:

| Часть | Где | Ответственность |
|---|---|---|
| Video, VideoSource, состояние и команды | Nodes либо отдельный NodesMedia | API без UIKit/AppKit, удобный для тестов модели |
| Драйвер воспроизведения | Общий Apple-слой с AVFoundation | Player/item, наблюдения, ошибки, замена источника |
| UIView/NSView и интеграция с EmbeddedHolder | NodesUIKit / NodesAppKit | Поверхность, рамки, видимость, доступность |

Точное размещение выбрать в V0 по графу зависимостей. Если нужен независимый продукт
NodesMedia, платформенные регистрации тоже должны подключаться опционально, без цикла
NodesMedia → NodesUIKit → NodesMedia. Не создавать отдельные пакеты только ради имени.
Linux проверяет модель и layout; воспроизведение на Linux этим планом не обещается.

## 4. Эскиз API

```swift
let video = Video(source: .url(url))
video.placeholder = PosterNode() // Собственная нода приложения; API пока эскиз.
video.preload = .none
video.autoplay = false
video.contentMode = .fit
video.isMuted = true
video.isLooping = false
video.play()
video.pause()
```

Эскиз, не существующий API. Источник первой версии — URL файла или HTTP(S) URL;
ограничения схем проверяются до начала загрузки. Большие Data не являются основным
способом передачи видео. Авторизованные потоки и нестандартные resource loaders —
последующее расширение с отдельным контрактом.

Минимальные возможности:

- смена/очистка source; старое содержимое не появляется после смены;
- `.fit` и `.fill` с определённой обрезкой; пропорции учитывают ориентацию видео;
- собственная placeholder-нода: Image с постером, skeleton, текст или композиция;
  отдельные свойства для GIF и каждого другого формата не нужны;
- play/pause, muted, volume в определённых пределах, loop;
- явный retry после ошибки;
- наблюдаемые готовность, воспроизведение и ошибка через StateCore;
- размеры видео и длительность после получения метаданных; неизвестная длительность
  представляется явно, не числом 0.

Seek нужен будущему плееру, но не обязателен первому Video. Если включать его сейчас,
определить допустимый диапазон, отмену предыдущего seek и результат при live/неизвестной
длительности. Высокочастотные изменения currentTime не должны вызывать полную раскладку.

### 4.1. Placeholder, предзагрузка и первый кадр — согласованное уточнение

**Собственная нода.** Предлагаемый API — `placeholder: Node?`. Video удерживает ноду и
монтирует её как своё содержимое ожидания в рамке видео. Один экземпляр нельзя монтировать
сразу в нескольких Video. Фабрика вместо экземпляра допустима при уточнении API, но нода
не пересоздаётся на каждый кадр или обновление состояния.

Если нода не задана, показывается фон темы. Приложение может передать Image с локальным
или удалённым постером, skeleton, подпись или композицию с индикатором и действием retry.
Удалённый постер загружается независимо через Image; его ошибка не блокирует Play и не
становится ошибкой видео. Пропорции задаются заранее, чтобы обе загрузки не меняли размер
карточки неожиданно. Для оформления ожидания и ошибки ноде доступно наблюдаемое состояние
Video; точный контракт определить в V1 без сильного цикла Video → placeholder → Video.

**Анимация placeholder.** Пользовательская анимированная нода допустима. Декодирование
GIF не входит в Video и не считается уже реализованным в Image. Анимация останавливается
вне экрана и после появления видео; учитывается Reduce Motion. После завершения перехода
placeholder демонтируется, даже если его объект сохраняется для будущего повторного
показа. Нельзя держать невидимую анимацию и её загрузки работающими постоянно.

**Порядок поверхностей.** Placeholder должен действительно находиться поверх видео.
Проверить это в V0: текущие embedded views расположены поверх рисованных слоёв.
Если прямой EmbeddedNode не обеспечивает композицию, использовать контейнер с отдельной
встроенной поверхностью и placeholder. Не рисовать ноду под непрозрачным UIView/NSView.
Проверить clipping, отсутствие двойного монтирования, дублирования доступности и
перехвата прокрутки оверлеем.

Три независимые настройки:

| Настройка | Назначение | По умолчанию |
|---|---|---|
| preload | Подготовка видео до запроса Play | `.none` |
| autoplay | Автоматический запрос Play при допустимой видимости | `false` |
| placeholder | Представление до первого кадра | Собственная нода или фон темы |

**Без предзагрузки.** При `.none` до Play не начинается подготовка media item, извлечение
кадра или запрос метаданных видео. Пустую поверхность создать можно. Сетевой placeholder
имеет независимую загрузку. Play, в том числе разрешённый autoplay, начинает подготовку
даже при `.none`: запрет относится к работе до запроса воспроизведения.
Нельзя извлекать постер из сетевого видео при `.none`, скрыто запуская загрузку.

**Опциональная предзагрузка.** Режимы `.metadata` и `.automatic` — следующее расширение V5.
Это политика компонента, не гарантия точного числа загруженных байтов. До реализации
и проверки платформы не выставлять их в публичном API как работающие возможности.
Подготовка ограничивается окрестностью viewport и бюджетом числа задач/подготовленных
видео. Выход из этой области, скрытие экрана и неактивность приложения останавливают
подготовку и освобождают ресурсы. Ограниченный бюджет соседей — явное исключение из
освобождения ресурсов невидимых видео, а не создание player для каждой строки ленты.

**Приоритет Play.** Явное действие пользователя важнее фоновой подготовки: планировщик
освобождает слот и при необходимости отменяет подготовку соседей. Не обещать точный
сетевой приоритет там, где платформа его не предоставляет.

**Последовательность показа:**

```text
Placeholder → Play → placeholder + индикатор → готов первый кадр → видео
                                 ↓
                       сообщение ошибки + «Повторить»
```

- Подготовка и ошибка — разные состояния. Ошибка прекращает индикатор, позволяет показать
  сообщение и retry. Таймаут подготовки и отмену определить в V1; временная буферизация
  сама по себе не объявляется terminal error.
- Placeholder снимается по готовности первого кадра текущего источника, а не только
  media item. Позднее событие прежнего источника не снимает новый placeholder.
- Короткое плавное исчезновение placeholder допускается поверх готового кадра. При
  Reduce Motion — без анимации. Между постером и видео не должно быть пустой/чёрной вспышки.
- Обычная пауза сохраняет текущий кадр, не возвращает постер. При buffering после начала
  показа сохраняется кадр, при необходимости с индикатором поверх.
- После освобождения сессии при remount placeholder допустим до нового готового кадра.
  Смена source очищает кадр прежнего источника и возвращает placeholder.

Первая версия включает собственную ноду, отключённую предзагрузку, индикатор подготовки,
ошибку с повтором и корректный переход к кадру. GIF-декодер и автоматическая предзагрузка
не являются условием выпуска первой версии; жизненный цикл собственной анимации — является.

## 5. Состояние и готовность

Не смешивать «данные готовы», «первый кадр показан» и «пользователь хочет воспроизведение».
Предлагается разделить:

- загрузку: empty / loading / ready / failed;
- фактическое воспроизведение: paused / waiting / playing / ended;
- признак готовности первого кадра для снятия постера;
- намерение приложения: play или pause.

Готовый media item сам по себе не является доказательством показанного кадра. Постер
убирается по готовности поверхности. Buffering не становится terminal error.
Ошибки имеют Sendable-представление с понятным сообщением и диагностикой; исходные
платформенные объекты не передаются в layout. Отмена/замена источника не показывается
как ошибка пользователю.

## 6. Жизненный цикл и ресурсы

Безопасное поведение по умолчанию: preload `.none`, autoplay выключен, звук выключен. Автозапуск —
явная настройка; когда его включили, он подчиняется видимости и состоянию приложения.

- Один Video владеет одной сессией воспроизведения; общий player на все ноды не создаётся.
- Нода не на экране, экран скрыт или приложение неактивно: воспроизведение приостановлено.
  После возвращения возобновляется только прежнее намерение play; ручная пауза сохраняется.
- `isShown` и попадание во viewport проверяются отдельно. Обрезанный до нулевой рамки
  EmbeddedHolder не гарантирует остановку звука или загрузки.
- После unmount снять наблюдения и time observer, остановить задачи и освободить player/item.
  Для того же объекта ноды можно сохранить логическую позицию и намерение, но для VOD
  восстановить их только после готовности; live не обещает возврат к прежнему времени.
- Смена source увеличивает поколение, очищает состояние старого источника и отменяет
  связанные операции. Поздние callbacks не меняют новую сессию.
- Не создавать по player на каждую строку большого списка: вне видимой области ресурсы
  освобождаются, подготовка ограничена. Координация «одно активное видео на ленту» —
  отдельная политика приложения, а не глобальный singleton компонента.
- Player/наблюдения управляются с определённой изоляцией. Нельзя обходить Swift Concurrency
  через запрещённые в AGENTS.md аннотации.

## 7. Размер, поверхность и взаимодействие

До загрузки метаданных размер определяется layout: явной высотой/соотношением сторон
или документированным placeholder-размером. После загрузки автоматическое изменение
пропорций допускается только выбранной политикой, чтобы лента не прыгала неожиданно.
Пустой источник и ошибка не должны схлопывать явно заданную рамку.

Поверхность без элементов управления не забирает жест прокрутки, клавиши или фокус
пульта без необходимости. Касание не запускает видео скрытым неописанным правилом:
приложение явно задаёт действие. На TV команды play/pause относятся только к выбранному
или активному компоненту, не ко всем видео в дереве сразу.

Доступность: осмысленное название и состояние для содержательного видео; декоративное
видео можно исключить из чтения. Если воспроизведение доступно пользователю, действия
play/pause должны быть доступны без опоры только на визуальные кнопки. Фокус и
пользовательская пауза сохраняются при обновлении состояния.

## 8. Сеть, звук и платформы

Сетевое воспроизведение первой версии поручаем AVFoundation; не загружаем полный файл
через ImageCache или будущий HTTPClient перед показом. Постоянный disk cache, offline
загрузки и согласование с HTTP-кэшем требуют отдельной задачи. Не обещать, что URLSession
настройки общего HTTP-клиента автоматически применяются к видео.

Первая приёмка — короткий локальный файл и HTTP(S) VOD с документированным тестовым
форматом. HLS/live выделить отдельной проверкой, не считать поддержанными только по
наличию URL API. Возможность декодирования зависит от платформы и медиа-формата.

Компонент не перенастраивает глобальную аудиосессию при создании каждой ноды. Приложение
или общий медиа-сервис задаёт звуковую политику; адаптер учитывает прерывания и смену
маршрута. Фоновое воспроизведение, блокировка экрана и внешние маршруты не обещаются
первой версией. Поддерживаемые цели: iOS/iPadOS, tvOS, macOS и Catalyst; фактические
проверки каждой платформы фиксируются отдельно.

## 9. Этапы реализации и приёмка

| Этап | Работа | Проверка |
|---|---|---|
| V0 | Выбрать размещение, прототип поверхности и placeholder | Локальное видео в scroll; placeholder над видео, clipping, порядок, кадр и звук на iOS/Mac |
| V1 | Модель source/state/intent, placeholder-контекст и driver-контракт | Linux-тесты модели; preload none, поколения, pause/resume, смена source, ошибка/таймаут подготовки |
| V2 | AVFoundation и адаптеры UIKit/AppKit | Локальный и сетевой VOD, первый кадр, ошибка/retry, завершение и loop |
| V3 | Видимость, ресурсы, звук и доступность | Scroll, hide/show, unmount/remount, прерывания, отсутствие утечек и фонового звука |
| V4 | Демо и полная матрица проверок | iPhone/iPad/TV Simulator, Mac, сборка Catalyst; отдельные проверки устройств |
| V5, расширение | Metadata/automatic и ограниченная подготовка соседей | Бюджет, приоритет Play, отмена и освобождение ресурсов при выходе из области подготовки |

В демо: локальное видео с постером, сетевое видео, fit/fill, внешние кнопки play/pause
и mute как демонстрация API, уход из экрана и возврат, намеренно неверный URL.
Добавить собственную placeholder-ноду, медленный первый кадр, ошибку постера и ошибку
видео с повтором. Эти кнопки не являются новым публичным компонентом Player.

Тесты: отмена при подготовке, быстрые смены source, поздняя ошибка старого item, pause во
время buffering, конец и loop, ориентация/пропорции, скрытие во вложенном scroll,
размонтирование и освобождение наблюдений. Модель проверяется fake driver, но реальный
первый кадр и управление платформой — интеграционными тестами.

Дополнительная приёмка: при `.none` до Play сервер не получает запросов к видео,
даже если нода видима; постер загружается отдельно. Проверить autoplay, стабильный размер,
сохранение кадра на паузе, снятие placeholder по первому кадру, Reduce Motion, остановку
анимации вне экрана и после перехода, освобождение её ресурсов. Для V5 отдельно проверить
лимит подготовки и приоритет пользовательского Play.

Использовать короткие локальные фикстуры с разрешённым использованием; сетевые тесты —
локальный сервер с поддержкой требуемых запросов, без зависимости от чужого публичного
видео. Playhead/status не заменяют визуальную проверку поверхности. Для оценки памяти
и плавности отдельно проверить несколько видео при прокрутке на устройстве.

Команды сборки, Simulator-тесты и deadline — по AGENTS.md. Если нет устройства, это
«нет доступа»; непроверенная платформа остаётся открытой частью приёмки.

## 10. Что оставить будущей задаче Player

Player должен использовать тот же механизм воспроизведения и Video-поверхность,
добавляя controls, timeline, seek, полноэкранный показ и платформенные возможности.
Не закладывать второй независимый player внутри UI-плеера. До его проектирования
сохранить границу «сессия воспроизведения → поверхность → элементы управления»;
публичное внедрение внешнего AVPlayer пока не обязательно.

Открытые решения V0: размещение модулей, точный API состояния и наблюдений, порядок
поверхности среди рисованных нод, восстановление позиции при remount и правила
