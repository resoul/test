# ADR 0008 — Проход размещения переиспользует измерение ребёнка родителем

Дата: 2026-09-11. Закрывает дефект #14.

## Контекст

`FlexboxEngine.layoutContainer` на каждом уровне измерял контейнер заново под
`(.exact(frame.width), .exact(frame.height))`, а `resolveLines` дополнительно измерял каждого
ребёнка под `.exact(main)` после измерения под `.atMost` родителя. Оба ключа отличались от
ключа, под которым поддерево уже было измерено, поэтому каждый уровень промахивался всем
поддеревом: O(depth²) — цепочка глубины 200 (1000 нод) считалась 89 ms в Release, глубина 30
(272 ноды) — 3.5 ms.

## Решение

Две точки переиспользования, обе — только при доказуемо одинаковом результате:

1. `resolveLines`: item, который не вырос и не сжался и чей basis — его natural main-размер
   (`main == natural.parentSize.main`), не измеряется под `.exact(main)`: измерение под
   `.atMost` родителя, из которого взят basis, и есть его измерение — дети получили бы
   то же доступное пространство.
2. `layoutContainer`: контейнер, чей frame по cross-оси равен пространству, которое
   родитель предлагал своим items (`availableCross` из constraint'а родительского
   измерения), а по main-оси — его natural размеру, берёт из кэша измерение под
   child-constraint родителя `(atMost availableMain, atMost availableCross)` вместо
   `(exact, exact)`. Дети видят одинаковое доступное пространство в обоих случаях; свой
   natural размер контейнера размещение не использует — оно кладёт по `frame`.

Всё остальное — item, который flex'ился, контейнер уже своего пространства (не
stretched, явный размер), корень, absolute-дети — измеряется под `.exact` как раньше.

## Последствия

- Число измерений линейно по числу нод: глубина 200 — 5.8 ms Release (было 89), 30 —
  0.8 ms (было 3.5); в debug depth 200: 966 → 51 ms, промахов 101k → 1.8k.
- 40 референсных скриншотов совпали побайтно; 295 тестов.
- Граница: процентные размеры детей в auto-контейнере, который *не* растянут,
  по-прежнему резолвятся под `.exact` (переиспользования нет) — поведение не менялось.
- `BasisItem` несёт `natural: FlexMeasureResult` (internal).
