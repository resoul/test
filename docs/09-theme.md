# Тема и токены

## Решение

**Статус: согласовано.**

- У библиотеки есть **своя тема по умолчанию**: пользоваться именованными значениями можно
  сразу, без настройки.
- Пользователь может создать **свою тему** и подставить её вместо стандартной.
- Сырые числа всегда разрешены: `.padding(12)` работает наравне с `.padding(<токен>)`.

Всё ниже — **предложено**, если не сказано иначе. Решения 2026-09-27 — в разделах ниже с
пометкой «согласовано».

## Токены отступов

Отступы (`padding`, `gap`, `margin`) принимают значение, которое можно задать числом или
именем из шкалы темы, так же как пороги `from:` принимают число или имя
([04](04-conditionals-and-responsive.md#именованные-пороги)).

Шкала по умолчанию — сетка 4 pt:

| Шаг | pt |
|---|---|
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 12 |
| 5 | 16 |
| 6 | 24 |
| 7 | 32 |
| 8 | 48 |
| 9 | 64 |

### Имена отступов — вариант B

Имена отступов не должны путаться с именами порогов (`.sm`/`.md`/…): в одной строке
встречаются оба, например `.padding(<отступ>, from: .md)`. Компилятор их не спутает (это
разные типы), а человек может.

| Вариант | Пример | Плюсы | Минусы |
|---|---|---|---|
| A. Размеры | `.padding(.m, from: .md)` | коротко, привычно | `.m` и `.md` рядом читаются как одно и то же |
| B. Номера шагов, как в Tailwind | `.padding(.s4, from: .md)` | не пересекается с порогами, шкалу легко расширять | номер надо знать или смотреть в таблицу |
| C. Смысловые имена | `.padding(.regular, from: .md)` | читается без таблицы | трудно назвать 9 ступеней; `regular` пересекается с size class |

**Статус: согласовано — вариант B.** Tailwind на практике показал, что числовые шаги
отступов и именные пороги (`p-4 md:p-6`) хорошо уживаются в одной записи.

Шаг `.sN` соответствует строке таблицы выше: `.s1` = 2 pt, `.s5` = 16 pt, `.s9` = 64 pt.

## Реализация

`Spacing` (`.s1` … `.s9`) и `SpacingScale` (`.standard` = 2, 4, 8, 12, 16, 24, 32, 48, 64) —
в `LayoutCore`. Модификаторы отступов принимают и число, и шаг. Шаги превращаются в точки в
`apply`/`measure` по переданной шкале; `LayoutSpecProviding.layoutSpacing` даёт свою шкалу
view (по умолчанию `.standard`). Модуля `Theme` с цветами и типографикой ещё нет.

## Где живёт тема

**Статус: согласовано (2026-09-27).**

- **Отдельный модуль `Theme`**, только Foundation, зависит от `LayoutCore`. В нём —
  независимые описания: цвета, типографика, радиусы, параметры анимаций, пороги, шкала
  отступов (тип шкалы остаётся в `LayoutCore`, тема ссылается на него). Тема по умолчанию —
  здесь.
- Создание платформенных шрифтов и выполнение анимаций остаются в адаптерах и рендерере.
  `NodesRender.TextStyle` целиком не переезжает: в `Theme` — нейтральное описание
  типографики (размер, насыщенность, межстрочный интервал, ведение), из которого рендерер
  строит свой стиль. Так же параметры анимации (длительность, кривая) отделены от механизма
  `withAnimation`.
- `Color` остаётся конкретным цветом. Выбор светлого или тёмного значения делается при
  разрешении токена темы, поэтому отрисовка и интерполяция работают с уже определёнными
  цветами.

Зависимости: `LayoutCore ◄── Theme ◄── Nodes`; адаптеры обычных view (`LayoutUIKit`,
`LayoutAppKit`) тоже могут зависеть от `Theme`.

## Состав темы по умолчанию

**Статус: согласовано (2026-09-27)** — все категории, небольшими наборами:

| Категория | Начальный набор |
|---|---|
| Отступы | существующие `.s1` … `.s9` |
| Цвета | фон, поверхность карточки, основной и второстепенный текст, акцент, текст на акценте, разделитель, опасное действие |
| Типографика | крупный заголовок, заголовок, основной текст, подпись, кнопка |
| Радиусы | без скругления, малый, средний, большой |
| Анимации | короткая реакция, обычное изменение, переход |
| Пороги | существующие `.sm` … `.xxl` с возможностью переопределения |

Имена токенов — предложить при реализации (стиль как у отступов: не путаться с порогами и
между категориями).

Сырые значения остаются доступны: тема даёт значения по умолчанию, явно заданный цвет или
отступ имеет приоритет.

## Распространение по дереву

**Статус: согласовано (2026-09-27) — по дереву, частичными переопределениями.**

Поддерево может заменить только часть темы — например, акцент или режим светлый/тёмный —
и продолжает наследовать остальное, включая последующие изменения родительской темы. Для
тёмной карточки на светлом экране не нужно копировать всю тему.

## Условия отображения

**Статус: согласовано (2026-09-27).**

Тема задаёт палитры и наборы; **окружение** сообщает условия: режим (светлый/тёмный),
повышенный контраст, масштаб текста, уменьшение движения. Адаптер получает системные
настройки, приложение может переопределить режим (для всего дерева и для поддерева).

- Типографика учитывает масштаб текста.
- Анимации учитывают уменьшение движения.
- Это часть поддержки системной доступности, как рекомендует Apple.

Переключение светлого/тёмного режима не меняет пороги и отступы: изменение этих значений —
отдельная настройка темы.

## Смена темы и анимация

**Статус: согласовано (2026-09-27).**

- Без `withAnimation` новая тема применяется сразу.
- Внутри `withAnimation` плавно меняются поддерживаемые значения: цвета, радиусы, геометрия.
- Смена семейства шрифта не обещает плавного превращения одного шрифта в другой.
- Порог `Breakpoint` применяется сразу; анимируется получившееся изменение расположения, а
  не сам порог.
- Системное переключение (режим, контраст, масштаб текста) по умолчанию не запускает
  дополнительной анимации библиотеки.
- Изменение метрик (отступы, шрифты, пороги) требует новой раскладки; изменение только
  цвета — обновления отрисовки. Точечную оптимизацию (не раскладывать при смене цвета)
  можно добавить позже.

## Обычные view

**Статус: согласовано (2026-09-27): обычным `UIView`/`NSView` доступна вся тема.**

Иначе в смешанном экране две системы оформления: одна для нод, другая для стандартных
элементов. Начать с явной передачи темы владельцу view или адаптеру. Автоматически
перекрашивать произвольные компоненты UIKit/AppKit библиотека не обязана, но приложение
должно иметь возможность взять из общей темы цвет, шрифт и отступ.

## Пороги

**Статус: согласовано (2026-09-27).**

Сейчас `.md` сразу означает число 600 (`BreakpointWidth.md` в `LayoutCore/DSL/Tokens.swift`).
Чтобы тема могла менять `.md`, имя порога сохраняется как токен до подготовки раскладки и
разрешается по теме там же, где шаги отступов. Явно написанное число (`from: 600`) остаётся
числом. Пороги сравниваются с доступной шириной контейнера.

## Когда токен превращается в число

При подготовке снимка на main. Фоновый движок получает только числа: он не знает ни
темы, ни токенов и остаётся чистой функцией.

Следствие: **смена темы должна запрашивать новый снимок и пересчёт раскладки**, потому что
меняются числа. В Trellis смена environment resolve не вызывает (D13); для Espalier это правило
пересматривается для токенов темы.
