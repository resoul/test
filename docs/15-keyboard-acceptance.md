# Клавиатура: список приёмки

Что из заявленного про клавиатуру и поля ввода **не проверено**, и чем это проверять. Это
не план реализации (он в [13-controls.md](13-controls.md)) и не реестр дефектов
([defects.md](defects.md)): здесь только возможности, которые сейчас нельзя назвать
работающими, потому что ни один тест не показывает их работу.

## Что проверено сейчас

Модельные тесты: отступ клавиатуры укорачивает раскладку, `reveal` поднимает поле, рамка
вложенной ноды и её обрезка прокруткой, `TextField` (текст от пользователя и от кода, Return
`.next`/`.done`). UI-тест iOS `KeyboardTests` на **iPhone 17 Simulator**, экран Sign Up
(`OPEN_FORM=1`): по касанию поле получает фокус и появляется клавиатура; поле над ней;
Return в Name переводит клавиатуру в Email; набранное доходит до модели; перетаскивание
текста вниз убирает клавиатуру (проверяется итог: клавиатуры больше нет).

Из этого не следует ничего, кроме написанного: успех на iPhone-симуляторе не закрывает
iPad, Mac, TV и устройство.

## Правила закрытия пункта

- Пункт закрыт, когда назван тест (или ручной прогон с описанием шагов), платформа и дата,
  и критерий пункта проверяется в нём наблюдением, а не отсутствием ошибки.
- Simulator не выдаётся за устройство. Пункт, проверенный на Simulator, так и записывается.
- Тест, который смотрит только итог, не закрывает пункт про процесс (см. K1, K2).
- Падение теста клавиатуры на медленной машине сначала разбирается по этапам (касание →
  фокус → клавиатура → срок; дефект 212), и только потом считается дефектом продукта.

## Пункты

Каждый пункт — «не проверено», пока не записано иное.

### K1. Клавиатура идёт за пальцем кадр за кадром при интерактивном скрытии

- **Заявлено:** `Scroll.keyboardDismissal = .interactive`; `keyboardInset` меняется во время
  перетаскивания, поле и нижняя панель следуют за клавиатурой.
- **Покрыто:** только итог — после жеста клавиатуры нет.
- **Критерий приёмки:** во время удержанного касания верх клавиатуры следует за пальцем
  (расхождение не больше заданного числа точек) минимум в N разных положениях, а
  `keyboardInset` за это время убывает без скачков и возврата; поле над клавиатурой не
  перекрывается ни в одной выборке. Жест отпущен над серединой пути — клавиатура возвращается,
  под серединой — уходит; в обоих случаях итоговое положение согласовано с `keyboardInset`.
- **Как проверять:** XCUITest не может брать выборки, пока идёт блокирующий жест: нужен
  учёт на стороне демо (значения `keyboardInset` с метками времени, доступные тесту после
  жеста) или запись экрана с покадровым разбором. Один итоговый кадр критерием не является.

### K2. Подъём клавиатуры идёт по её кривой и длительности

- **Заявлено:** раскладка перестраивается с кривой и длительностью клавиатуры.
- **Известно:** отступ приходит вне блока анимации UIKit, поле встаёт на место без
  анимации.
- **Критерий приёмки:** при появлении и скрытии положение поля меняется не скачком, а за
  время, близкое длительности клавиатуры, минимум в N промежуточных положениях.
- **Как проверять:** как K1 — покадровый учёт; на Simulator — с включёнными обычными
  анимациями («Slow Animations» выключены).

### K3. Плавающая, закреплённая и разделённая клавиатура iPad

- **Заявлено:** отступ считается по пересечению кадра клавиатуры с окном, а не по высоте
  экрана; поддержан Stage Manager.
- **Критерий приёмки (iPad, ориентации обе):** закреплённая — отступ равен высоте; плавающая,
  не заходящая в окно, — отступ 0, поле не прокручивается лишний раз; перетаскивание
  плавающей клавиатуры через поле — поле остаётся доступным; переход закреплённая ↔
  плавающая во время правки — отступ согласован; окно Stage Manager меньше экрана — отступ
  по пересечению.
- **Как проверять:** UI-тест на iPad Simulator (в списке есть iPad Pro 11/13-inch, iPad
  mini) плюс ручной прогон плавающей клавиатуры (жест щипка по клавиатуре).

### K4. Внешняя (аппаратная) клавиатура

- **Заявлено:** Tab/Shift-Tab ведут по полям в порядке дерева; Return — `onSubmit`/следующее
  поле; Space и Return нажимают контрол в фокусе.
- **Покрыто:** Return `.next`/`.done` от экранной клавиатуры; Tab по полям тестами не
  проверялся.
- **Критерий приёмки:** при подключённой аппаратной клавиатуре экранная не показывается,
  `keyboardInset` 0, ввод доходит до поля, Tab и Shift-Tab обходят поля в порядке дерева
  и возвращаются по кругу или выходят по правилу экрана (правило записать), фокус дерева и
  first responder совпадают после каждого перехода.
- **Как проверять:** Simulator с «Connect Hardware Keyboard»; клавиши — через XCUITest
  (`typeKey`) или ручной прогон.

### K5. Другие режимы скрытия клавиатуры

- **Заявлено:** `Scroll.keyboardDismissal` — `.none`, `.onDrag`, `.interactive`; касание вне
  полей; Escape на iPad.
- **Покрыто:** только `.interactive` в одном UI-тесте; `.none` и `.onDrag` не проверялись.
- **Состояние:** скрытие по касанию вне полей и по Escape в коде адаптера не найдено (поиск по
  `Sources/NodesUIKit`: `resignFirstResponder` только при смене фокуса в `Embedded.swift`,
  Escape — лишь общее соответствие клавиши команде) — **не сделано**, а не «не проверено».
- **Критерий приёмки:** для каждого режима — тест: `.none` — жест не убирает клавиатуру;
  `.onDrag` — убирает в начале жеста; для касания вне полей и Escape — сначала решение, нужны
  ли они, затем тест.

### K6. Двойной учёт нижнего отступа

- **Заявлено:** нет двойного учёта нижнего отступа клавиатуры, безопасной области и панели.
- **Критерий приёмки:** экран с панелью снизу (кнопка «Отправить» над клавиатурой):
  расстояние между панелью и верхом клавиатуры равно расстоянию у экрана без безопасной
  области нужного значения — не больше и не меньше; то же при закрытой клавиатуре (отступ
  безопасной области учтён один раз). Проверять на устройстве с вырезом/индикатором Home и
  на iPad.

### K7. Правка не прерывается обновлением дерева, поворотом и сменой размера

- **Критерий приёмки:** во время правки дерево перерисовывается (изменилось состояние) —
  поле остаётся first responder, курсор, выделение и marked text сохраняются; поворот и
  смена размера окна — то же, поле остаётся над клавиатурой.

### K8. Порядок фокуса и first responder

- **Критерий приёмки:** фокус дерева и клавиатурный фокус согласованы при касании, Tab,
  Return `.next` и программном `beginEditing()`/`endEditing()`; поле вне видимой части не
  получает фокус от Tab, пока не показано (или показывается прокруткой — записать правило).

### K9. Ввод на разных языках, IME, диктовка, автозаполнение

- **Заявлено:** «даром» (системное поле).
- **Критерий приёмки:** ручной прогон — китайская или японская клавиатура (marked text),
  диктовка, автокоррекция, подстановка email; `onChange` получает подтверждённый текст, а не
  промежуточный marked text, если не задано иное (записать правило).

### K10. Доступность поля вне экрана

- **Известно:** поле вне видимой части обрезано до нуля, а не скрыто; проверено только
  через XCUITest.
- **Критерий приёмки:** живой VoiceOver (iPhone) — доходит до поля вне экрана, прокручивает
  к нему, ввод работает; Accessibility Inspector показывает рамку и порядок чтения.

### K11. Mac (`NSTextField`)

- **Заявлено:** Tab/Shift-Tab по полям, Return — `onSubmit`, Escape — `Command.cancel`.
- **Состояние:** поле на Mac не показывается — **не сделано**, не «не проверено».
- **Критерий приёмки после реализации:** те же сценарии, что на iOS (ввод, Return `.next`,
  Tab, редактирование при перерисовке дерева), UI-тест Mac; отдельный пункт — совместимость
  с фокус-кольцом и доступностью (дефект 200).

### K12. TV

- **Заявлено:** поле в фокусе по Select открывает системный экран ввода; `EmailField`
  передаёт `content`.
- **Состояние:** поле на TV не показывается — **не сделано**. Отдельно: на tvOS приведение к
  недоступному протоколу всё равно проходит (дефект 210), поэтому любой новый код вокруг
  клавиатуры на TV проверять проверкой платформы во время выполнения.
- **Критерий приёмки после реализации:** UI-тест tvOS: фокус на поле, Select открывает ввод,
  введённое доходит до модели, Menu возвращает фокус на поле; ни один скрытый вид не
  попадает в порядок фокуса.

### K13. Устройства

- Всё выше проверено, где проверено, на Simulator. Ни один пункт не проверен на устройстве:
  задержки касания и клавиатуры (дефект 212) на настоящем железе неизвестны.
- **Критерий приёмки:** K1, K2, K3, K6 и K9 — минимум один прогон на iPhone и один на iPad
  (устройства), запись: модель, версия, результат; при недоступности устройства —
  «нет доступа», а не «пройдено».
